# /팀매트릭스 - 멀티 도메인 Phase 1.5: 도메인별 교차 분석 + 통합 매트릭스

실행 옵션: $ARGUMENTS
(예: all(기본), {agent-id}, merge)

## 목적

1. 각 도메인 에이전트가 자체 소스 교차 분석 + 커버리지 매트릭스를 생성합니다
2. 오케스트레이터가 도메인별 매트릭스를 **통합 매트릭스**로 병합합니다
3. 크로스 도메인 경계 TC를 식별합니다

## 전제 조건

- `/팀소스분석`이 완료되어 `_summaries/{agent-id}/` 에 요약 파일이 존재할 것
- 각 에이전트당 최소 1개 이상의 요약 파일 필요 (4종 모두 있을 때 최적)

## 실행 절차

각 도메인 에이전트 Task에 전달하는 프롬프트:

```
당신은 {도메인명} 도메인의 전문 QA 에이전트입니다.

## 작업

- _summaries/{agent-id}/confluence_summary.md
- _summaries/{agent-id}/figma_summary.md
```

### Step 2: 오케스트레이터 병합 (Merge)

모든 도메인 매트릭스가 완료되면 오케스트레이터가 통합합니다.

#### 2-1. 매트릭스 병합

1. 각 도메인의 `coverage_matrix.md`를 순차 읽기
2. 통합 카테고리 트리 재구성:
   - 1차 카테고리 = 도메인명
   - 2차/3차 카테고리 = 도메인 내부 카테고리
3. 조합 ID 충돌 검사 (도메인 접두사로 방지)
4. 시트별 집계를 도메인별 + 전체로 산출
5. TC 수 산정 승수를 도메인별 + 전체로 산출

출력: `_summaries/merged_coverage_matrix.md`

#### 2-2. 중복 조합 탐지

동일한 테스트 차원 + 기대결과를 가진 조합을 식별합니다.

| 판정 | 기준 | 처리 |
|------|------|------|
| 완전 중복 | 차원값 + 기대결과 + 대상 시트 모두 동일 | 1개로 통합, 출처 도메인 병기 |
| 관점 중복 | 같은 화면/기능이지만 검증 포인트가 다름 | 둘 다 유지 |
| 비중복 | 차원값 또는 기대결과가 다름 | 둘 다 유지 |

#### 2-3. 크로스 도메인 분석

각 도메인의 `boundary_report.md`를 수집하여 크로스 도메인 TC를 생성합니다.

1. 모든 경계 보고서 수집
2. 양쪽 도메인이 동일 경계를 보고한 경우 → 크로스 도메인 TC 생성
3. 한쪽만 보고한 경우 → 상대 도메인 매트릭스에서 관련 조합 존재 여부 확인
4. 크로스 도메인 TC는 **유즈케이스 시트**에 배치 (3+ 상태 전이 조건 충족)

출력: `_summaries/cross_domain_analysis.md`

```markdown
# 크로스 도메인 분석 결과

## 경계 시나리오 매칭
| ID | 시나리오 | 도메인 A | 도메인 B | 매칭 유형 | TC 배치 |
|----|---------|---------|---------|----------|--------|
| CD-001 | 비로그인 펀딩 → 로그인 → 복귀 | funding | user | 양쪽 보고 | 유즈케이스 |

## 크로스 도메인 TC 조합
| ID | 시나리오 | 사전조건 | 실행절차 요약 | 관련 도메인 | 대상 시트 |
|----|---------|---------|-------------|-----------|----------|
| CDT-001 | ... | ... | ... | funding, user | 유즈케이스 |

## 통계
| 지표 | 수치 |
|------|------|
| 총 경계 시나리오 | {N} |
| 양쪽 보고 매칭 | {N} |
| 한쪽만 보고 | {N} |
| 크로스 도메인 TC | {N} |
```

## 인자별 동작

### all (기본)
- 모든 투입 에이전트의 매트릭스 생성 + 오케스트레이터 병합
- 예: `/팀매트릭스`

### {agent-id}
- 특정 에이전트의 매트릭스만 생성 (병합하지 않음)
- 예: `/팀매트릭스 funding`

### merge
- 기존 도메인별 매트릭스를 재병합 (도메인 매트릭스 재생성 없이)
- 예: `/팀매트릭스 merge`

### status
- 각 에이전트의 매트릭스 생성 상태 보고
- 예: `/팀매트릭스 status`

## 정확성 보장 규칙

- `/매트릭스` 커맨드의 R1~R5 규칙이 각 도메인 에이전트에 동일하게 적용됩니다
- 오케스트레이터 병합 시 추가 규칙:
  - **병합 R1**: 도메인 매트릭스 원본을 Read로 열어 확인한 뒤 병합 (기억 기반 병합 금지)
  - **병합 R2**: 도메인 간 동일 기능에 대한 모순 기술 탐지
  - **병합 R3**: 도메인별 용어를 통합 시 원문 유지 (한쪽 표현으로 통일하지 않음)

## 주의사항

- 도메인별 매트릭스 생성은 기존 `/매트릭스` 커맨드의 **전체 프로토콜**을 따름
- 경계 보고서는 매트릭스와 동시에 생성됨 — 별도 단계가 아님
- 통합 매트릭스는 사람 검토 필수 — 자동으로 Phase 2 진행 금지
- 단일 도메인이면 병합 단계를 건너뛰고 해당 도메인 매트릭스를 그대로 사용
