# /TC생성 - Phase 2: 테스트케이스 xlsx 생성 (시트별 분할 생성)

생성 옵션: $ARGUMENTS
(예: v1, 시트:명세기반, 시트:예외사항, 추가:네트워크오류)

## 실행 절차

### Step 0: 매트릭스 존재 확인
1. `_summaries/coverage_matrix.md` 파일 존재 여부 확인
2. **없으면**: "커버리지 매트릭스가 없습니다. `/매트릭스`를 먼저 실행해주세요." 안내 후 **중단**
3. **있으면**: 매트릭스의 생성일과 시트별 집계를 요약하여 사용자에게 표시

### Step 1: 정보 시트 생성
1. `_summaries/` 폴더의 요약 파일 4종을 읽기
2. `_summaries/cross_analysis.md` 교차 분석 결과 읽기
3. `규칙_TC포맷과소스.md`에서 포맷 조건 확인
4. `역할_QA전문가.md`에서 역할 컨텍스트 확인
5. 템플릿 참조: `설정_소스경로.md`의 "공통 로컬 경로" 참조
6. 정보 시트 작성:
   - 프로젝트 개요
   - 소스 URL 목록
   - 매트릭스 통계 반영 (총 영역 수, 예상 TC 수, 시트별 목표)
   - TC 버전 및 생성일

### Step 2: 시트별 분할 생성
각 시트를 **순차적으로** 생성합니다. 시트 하나를 완성한 후 다음 시트로 이동합니다.

#### 시트별 생성 프로토콜 (5개 시트 공통)
1. **매핑 추출**: `coverage_matrix.md`에서 해당 시트에 매핑된 조합 항목을 추출 (교차 분석 기반 항목 포함)
2. **수치 목표 확인**: "이 시트에서 최소 {N}개 TC 필요" (매트릭스 시트별 집계 참조)
3. **분류 플로차트 검증**: `기준_시트분류.md`의 플로차트로 각 매핑 항목이 현재 시트에 올바르게 배치되었는지 확인. 오배치 발견 시 올바른 시트로 이동
4. **소스 원문 확인 (R1 적용)**: 해당 시트의 매핑 항목과 관련된 요약 파일을 **Read 도구로 열어** 원문을 확인한 뒤 TC를 작성한다. 기억에 의존하여 기대결과를 작성하지 않는다
5. **TC 작성**: 각 매핑 항목에 대해 TC 1개 이상 작성
   - 교차 분석으로 추가된 TC도 해당 시트의 성격에 맞게 포함 (별도 시트 생성 금지)
   - ISTQB 기법은 매트릭스에 명시된 기법을 적용
   - 컬럼: 케이스번호, 테스트제목, 사전조건, 실행절차, 기대결과, 테스트결과, 예상시간, 비고
   - 예상시간: minute 단위, 소수점 첫째자리 (최소 0.5분)
   - **비고란 형식**: `{ISTQB 기법} │ {품질특성}:{하위특성}` (예: `동치분할 │ 기능적합성:정확성`)
   - **기대결과는 소스 원문 표현을 유지** (R3 적용): 동의어 치환 금지, 기술 용어·필드명·열거형 값은 원문 그대로
5-a. **원자적 분해 적용 (A1)**: `기준_실행단위분해.md` A1 분해 판정 플로차트를 적용
   - Q-A1: 기대결과에 독립된 검증 포인트가 2개 이상 → 분리
   - Q-A2: 실행절차에 서로 다른 결과를 확인하는 행위가 2개 이상 → 분리
   - Q-A3: 같은 UI 영역의 서로 다른 요소를 각각 동작 → 분리
   - **예외**: 정보 노출 그룹 확인은 1개 TC 허용
5-b. **컨텍스트 복제 적용 (A2)**: 매트릭스의 컨텍스트 복제 목록 참조
   - 공통 기능 TC를 모든 노출 컨텍스트에 복제
   - 사전조건에 "페이지: {컨텍스트명}" 명시
   - "위와 동일" 형태의 축약 금지 — 각 TC는 독립적으로 실행 가능해야 함
5-c. **플랫폼 UI 분리 적용 (A3)**: 매트릭스의 플랫폼 UI 분리 대상 참조
   - PC/Mobile 간 UI 차이가 있는 기능 → 플랫폼별 별도 TC 작성
   - 사전조건에 "Only PC" 또는 "Only Mobile" 명시
6. **시트 내 분할 판정 및 생성** (매트릭스 매핑 50행 초과 시):
   - **2-b. 시트 내 분할 판정**: 매트릭스 매핑 50행 초과 시 기능 영역 단위 분할 생성
     - 영역별 순차 생성: 영역A TC → 자기 점검 → 영역B TC → ...
     - 각 영역 완료 후 중간 보고: "{시트명} - {영역명}: {N}개 TC 완료"
   - **2-c. 품질 일관성 검증** (분할 시트에만 적용):
     | 검증 지표 | 첫 영역 | 마지막 영역 | 허용 편차 |
     |-----------|---------|-----------|----------|
     | 기대결과 평균 문자 수 | {N}자 | {M}자 | M ≥ N × 0.7 |
     | 실행절차 평균 스텝 수 | {N}단계 | {M}단계 | M ≥ N × 0.7 |
     | 매트릭스 1:1 커버율 | {N}% | {M}% | M ≥ 95% |
     허용 편차 미달 시: 마지막 영역 TC를 재점검하여 보충
7. **자기 점검**: 매트릭스 매핑 항목 대비 누락 TC가 있는지 1:1 대조. 누락 있으면 추가 작성
   - **열거 완전성 확인 (R4 적용)**: "N종" 수량이 명시된 매핑 항목은 N개 TC가 모두 존재하는지 확인
   - **품질 특성 커버리지 확인**: 해당 시트에 매핑된 ISO/IEC 25010 특성이 최소 1개 TC에 반영되었는지 확인
8. **시트 완료 보고**: "{시트명} 완료: {N}개 TC 작성 (매트릭스 목표: {M}개)"

#### 시트 생성 순서
| 순서 | 시트명 | 주요 기법 |
|------|--------|-----------|
| 1 | 명세기반 | 동치분할, 경계값분석, 조건기반, 결정테이블 |
| 2 | 예외사항 | 에러추측, 부정테스팅, 결함분류법 |
| 3 | 유즈케이스 | 상태전이, 시나리오테스팅, 분기커버리지 (E2E + 유저스토리) |
| 4 | 코드영향도 | 데이터흐름, 영향도분석 |
| 5 | Regression | 리스크기반 우선순위 |

#### 유즈케이스 시트 추가 프로토콜: 유저스토리 TC

유즈케이스 시트 생성 시, 기존 E2E TC 생성 후 **유저스토리 TC를 추가 생성**합니다.
`기준_유저스토리.md`를 참조하여 다음을 수행합니다:

1. **유저스토리 조합 추출**: 매트릭스의 `US-ID` 조합을 순회
2. **TC 변환**: 각 조합을 TC로 변환
   - 사전조건 = 사용자 상태 (State) + 사용자 상황 (Situation)
   - 실행절차 = 사용자 행동 시퀀스 (Action) — 반드시 2+ 행동
   - 기대결과 = 해당 조건 조합에서의 올바른 시스템 동작 (소스 원문 기반)
   - 비고란 = `시나리오테스팅 │ 기능적합성:적절성` 또는 `시나리오테스팅 │ 사용품질:유효성`
3. **겹침 방지 점검**: 기존 E2E TC와 동일 경로 + 동일 조건인 TC가 없는지 확인
4. **자기 점검**: 3축 각 값이 최소 1개 TC에 포함되었는지 (Each-choice)

### Step 3: 통합 검증
1. 전체 시트의 TC를 매트릭스와 대조
2. 커버리지율 산출: `(매트릭스 조합 중 TC가 존재하는 항목 수) / (총 매트릭스 조합 수) × 100%`
3. 커버리지율이 90% 미만이면 누락 항목을 식별하고 추가 TC 작성
4. **카테고리 트리 대비 검증 (A4)**: 매트릭스의 3단계 카테고리 트리의 모든 3차 항목에 최소 1개 TC가 존재하는지 1:1 대조. 누락 카테고리 = 누락 TC로 처리
5. **A1-A3 자기 점검**:
   - A1: 기대결과에 "~확인" 동사가 2개 이상인 TC가 없는지 확인 (있으면 분리)
   - A2: 공통 기능이 모든 노출 컨텍스트에서 개별 TC로 작성되었는지 확인
   - A3: 플랫폼 UI 분리 대상 기능이 PC/Mobile 별도 TC로 작성되었는지 확인
6. **TC 수 검증 (A5)**: 최종 TC 수가 승수 공식 예상치의 80% 이상인지 확인. 미달 시 누락 원인 분석
7. 시트별 TC 수 집계 보고

### Step 4: xlsx 파일 생성
1. Excel MCP(`excel` 서버)를 사용하여 직접 xlsx 생성
2. MCP 사용 불가 시 Python openpyxl 스크립트로 대체
3. 파일명: `{{프로젝트명}}_테스트케이스_{버전}.xlsx`
4. 최종 통계 출력:
   ```
   ## 생성 완료
   - 파일: {{프로젝트명}}_테스트케이스_{버전}.xlsx
   - 총 TC 수: {N}개
   - 매트릭스 대비 커버리지: {X}%
   - 승수 공식 예상 대비 달성율: {Y}%
   - 카테고리 트리 3차 항목 커버리지: {Z}%
   - 시트별: 명세기반({N}), 예외사항({N}), 유즈케이스({N}), 코드영향도({N}), Regression({N})
   - A1 분해 적용 TC: {N}건, A2 복제 적용 TC: {N}건, A3 플랫폼 분리 TC: {N}건
   ```

## 시트 구성 (6개)
| 시트명 | 내용 | 주요 기법 | ISO/IEC 25010 품질 특성 |
|--------|------|-----------|------------------------|
| 정보 | 프로젝트 개요, TC 통계, 소스 URL, 매트릭스 통계 | - | - |
| 명세기반 | 기능 요구사항 + 사용성 TC | 동치분할, 경계값, 조건기반, 결정테이블 | 기능적합성, 사용성(학습성/조작성/오류방지/접근성) |
| 예외사항 | 에러/예외 + 보안 TC | 에러추측, 부정테스팅, 결함분류법 | 신뢰성(결함허용성/복구성/성숙성), 보안(기밀성/무결성/인증) |
| 유즈케이스 | E2E 여정 + 유저스토리(행동 기반) TC | 상태전이, 시나리오테스팅, 분기커버리지 | 기능적합성(E2E/적절성), 사용품질(유효성) |
| 코드영향도 | 코드 변경 + 성능 TC | 데이터흐름, 영향도분석 | 호환성(상호운용성), 성능효율성(시간/자원/용량) |
| Regression | 기존 기능 + 이식성 TC | 리스크기반 우선순위 | 기능적합성(기존), 이식성(적응성), 호환성(공존성) |

> 분류 상세 기준은 `기준_시트분류.md`의 분류 의사결정 플로차트를 참조합니다.

## 개별 시트 생성 옵션

특정 시트만 생성하거나 재생성할 수 있습니다:
```
/TC생성 시트:명세기반      → 명세기반 시트만 생성
/TC생성 시트:예외사항      → 예외사항 시트만 생성
/TC생성 시트:유즈케이스    → 유즈케이스 시트만 생성
/TC생성 시트:코드영향도    → 코드영향도 시트만 생성
/TC생성 시트:Regression   → Regression 시트만 생성
```

개별 시트 생성 시에도 동일한 프로토콜(매핑 추출 → 수치 목표 → TC 작성 → 자기 점검)을 따릅니다.
