# /팀소스분석 - 멀티 도메인 Phase 1: 도메인별 병렬 소스 분석

실행 옵션: $ARGUMENTS
(예: all(기본), {agent-id}, {agent-id}:{source})

## 목적

투입된 도메인 에이전트들이 **동일한 소스를 각자의 도메인 렌즈로 독립 분석**하여, 도메인별 요약 파일을 생성합니다.

## 핵심 원칙: 같은 소스, 다른 렌즈

- 모든 투입 에이전트가 **동일한 소스 URL**을 분석합니다
- 각 에이전트는 `_agents/{agent-id}/domain_lens.md`의 렌즈를 적용하여 자기 도메인 관련 요소만 집중 추출합니다
- 소스를 에이전트별로 분배하지 않습니다 — 소스 분배 문제 제거

## 전제 조건

- `/팀배포`로 에이전트가 설정되어 있을 것
- `설정_소스경로.md`에 소스 URL이 설정되어 있을 것
- 각 에이전트의 `_agents/{agent-id}/domain_lens.md`가 작성되어 있을 것 (미작성 시 범용 분석으로 폴백)

## 인자별 동작

### all (기본)
- 투입된 모든 에이전트가 4개 소스를 병렬 분석
- 예: `/팀소스분석` 또는 `/팀소스분석 all`

### {agent-id}
- 특정 에이전트만 4개 소스 분석
- 예: `/팀소스분석 funding`

### {agent-id}:{source}
- 특정 에이전트의 특정 소스만 분석
- 예: `/팀소스분석 funding:figma`

### status
- 각 에이전트의 요약 파일 존재 여부 보고
- 예: `/팀소스분석 status`

## 요약 파일 품질 기준

각 요약 파일은 다음을 만족해야 합니다:

| 기준 | 설명 |
|------|------|
| 도메인 집중도 | 해당 도메인 관련 요소가 전체의 70% 이상 |
| 완전성 앵커 | 항목 유형별 개수 + 합계 테이블 존재 |
| 테스트 차원 열거 | 입력값/분기 조건/상태 열거 테이블 존재 |
| UI 구조 추출 | 화면 구조/공통 기능 노출 위치/PC-Mobile 차이 테이블 존재 |
| 역검증 결과 | 수행일 + 재열람 섹션 + 보정 여부 기록 |
| R1~R5 적용 | 기억 기반 작성 없음, 원문 표현 유지, 열거 완전성 확인 |

## 단일 도메인 폴백

투입 에이전트가 1개뿐이면 기존 `/소스분석 all`과 동일하게 동작합니다.
출력 경로만 `_summaries/{agent-id}/`로 변경됩니다.

## 주의사항

- 도메인 렌즈가 없는 에이전트는 범용 분석으로 폴백 (모든 요소 추출)
- 소스 URL이 없는 항목(예: GitHub URL 미설정)은 해당 소스 SKIP
- 각 서브에이전트는 독립 컨텍스트에서 실행 — 부모 에이전트의 컨텍스트를 소비하지 않음
- 중첩 깊이: 오케스트레이터(L0) → 도메인 에이전트(L1) → 소스 서브에이전트(L2) — 최대 2단계
