# /팀TC생성 - 멀티 도메인 Phase 2: 통합 매트릭스 기반 TC 생성

생성 옵션: $ARGUMENTS
(예: v1, {agent-id}:v1, 시트:명세기반)

## 목적

통합 매트릭스(`merged_coverage_matrix.md`)를 기반으로 각 도메인 에이전트가 비즈니스 기능별 서브에이전트를 활용하여 TC를 생성하고, 오케스트레이터가 최종 xlsx로 통합합니다.

## 전제 조건

- `/팀매트릭스`가 완료되어 `_summaries/merged_coverage_matrix.md`가 존재할 것
- 사람이 통합 매트릭스를 검토하고 승인했을 것
- 각 에이전트의 `_agents/{agent-id}/phase2_subagents.md`가 작성되어 있을 것 (미작성 시 서브에이전트 없이 도메인 에이전트 본체가 직접 생성)

## 실행 절차

### Step 0: 매트릭스 존재 확인

1. `_summaries/merged_coverage_matrix.md` 존재 여부 확인
2. 없으면 `/팀매트릭스`를 먼저 실행하도록 안내 후 중단
3. 있으면 통합 매트릭스 통계를 사용자에게 표시

### Step 1: 매트릭스 도메인별 분배

통합 매트릭스의 조합 행을 도메인 접두사로 분류합니다.

```
merged_coverage_matrix.md
├── FND-xxx 행 → funding-agent에 전달
├── USR-xxx 행 → user-agent에 전달
├── MKR-xxx 행 → maker-agent에 전달
└── CDT-xxx 행 → 크로스 도메인 TC (오케스트레이터가 직접 생성)
```

### Step 2: 도메인별 TC 생성 (병렬)

각 도메인 에이전트를 Task 도구로 병렬 실행합니다.

각 도메인 에이전트 Task에 전달하는 프롬프트:

```
당신은 {도메인명} 도메인의 전문 QA 에이전트입니다.

## 매트릭스 (이 도메인 해당 행만)
{도메인 접두사로 필터링된 매트릭스 행}

## 도메인 지식
- service_profile.md: {내용}
- business_rules.md: {내용}
- phase2_subagents.md: {내용}

## Phase 2 서브에이전트 구성
{phase2_subagents.md에 정의된 비즈니스 기능별 서브에이전트}

## 작업
1. 매트릭스 행을 비즈니스 기능별로 분류
2. 각 비즈니스 기능 서브에이전트를 Task로 병렬 실행
3. 서브에이전트 결과를 통합
4. A1~A5 자기 점검 수행
5. 결과를 _tc_data/{agent-id}/ 에 시트별 파일로 저장

### 서브에이전트별 TC 생성 프로토콜
각 서브에이전트는 `/TC생성` 커맨드의 Step 2 프로토콜을 따릅니다:
- 매핑 추출 → 수치 목표 확인 → TC 작성
- A1 원자적 분해, A2 컨텍스트 복제, A3 플랫폼 분리 적용
- R1~R5 정확성 보장 규칙 적용
- 비고란: {ISTQB 기법} │ {품질특성}:{하위특성}

### 크로스 기능 TC
서브에이전트 경계를 넘는 E2E 플로우(phase2_subagents.md의 "크로스 기능 플로우" 참조)는
도메인 에이전트 본체가 직접 작성합니다.

## 출력 형식
_tc_data/{agent-id}/
├── 명세기반.json      # [{케이스번호, 테스트제목, 사전조건, 실행절차, 기대결과, 테스트결과, 예상시간, 비고}, ...]
├── 예외사항.json
├── 유즈케이스.json
├── 코드영향도.json
├── regression.json
└── 생성보고.md        # TC 통계, A1~A5 적용 건수, 커버리지율
```

### Step 3: 크로스 도메인 TC 생성 (오케스트레이터)

`_summaries/cross_domain_analysis.md`의 CDT-xxx 조합에 대해 오케스트레이터가 직접 TC를 생성합니다.

- 주로 **유즈케이스 시트** 배치 (3+ 상태 전이, 2+ 도메인 횡단)
- 사전조건에 관련 도메인 명시
- 비고란에 `시나리오테스팅 │ 기능적합성:적절성` 등 태깅

출력: `_tc_data/cross_domain/유즈케이스.json`

### Step 4: 오케스트레이터 통합

#### 4-1. TC 수집
각 도메인 + 크로스 도메인의 `_tc_data/` 파일을 시트별로 수집합니다.

#### 4-2. 중복 제거 (Merge Engine)

| 판정 | 기준 | 처리 |
|------|------|------|
| 완전 중복 | 테스트제목 + 사전조건 + 기대결과 실질 동일 | 1개 유지, 비고에 "(도메인A+도메인B)" 출처 병기 |
| 관점 중복 | 같은 화면이지만 검증 포인트 다름 | 둘 다 유지 |
| 비중복 | 테스트 대상이 다름 | 둘 다 유지 |

#### 4-3. 케이스번호 체계 통합

```
{시트약어}-{도메인접두사}-{순번}

예시:
SP-FND-001  (명세기반-펀딩-001)
EX-USR-015  (예외사항-회원-015)
UC-CDT-001  (유즈케이스-크로스도메인-001)
```

시트 약어:
| 시트 | 약어 |
|------|------|
| 명세기반 | SP |
| 예외사항 | EX |
| 유즈케이스 | UC |
| 코드영향도 | CI |
| Regression | RG |

#### 4-4. 시트 분류 검증

`기준_시트분류.md`의 분류 플로차트로 모든 TC의 시트 배치를 재검증합니다.
오배치 발견 시 올바른 시트로 이동합니다.

#### 4-5. 통합 검증

`/TC생성` 커맨드의 Step 3 (통합 검증)을 전체 TC에 적용합니다:
- 매트릭스 대비 커버리지율 산출
- 카테고리 트리 대비 검증 (A4)
- A1~A3 자기 점검
- TC 수 검증 (A5)

### Step 5: 정보 시트 생성

1. 프로젝트 개요
2. 투입 도메인 에이전트 목록
3. 소스 URL
4. 도메인별 + 전체 TC 통계
5. 매트릭스 통계 (총 조합, 예상 TC, 실제 TC, 커버리지)
6. 크로스 도메인 TC 통계
7. TC 버전 및 생성일

### Step 6: xlsx 파일 생성

1. Excel MCP 또는 Python openpyxl로 xlsx 생성
2. 파일명: `{프로젝트명}_테스트케이스_{버전}.xlsx`
3. 최종 통계 출력:

```

## 인자별 동작

### v{N} (기본)
- 전체 도메인의 TC 생성 + 통합
- 예: `/팀TC생성 v1`

### {agent-id}:v{N}
- 특정 도메인만 TC 생성 (통합하지 않음)
- 예: `/팀TC생성 funding:v1`

### 시트:{시트명}
- 특정 시트만 재생성 (모든 도메인에서 해당 시트 재생성 후 통합)
- 예: `/팀TC생성 시트:명세기반`

### merge
- 기존 도메인별 TC 데이터를 재통합 (TC 재생성 없이)
- 예: `/팀TC생성 merge`

## 병렬 실행 구조

```

│

│   ├── Task: funding-agent
│   │   ├── Task: Project 서브에이전트    ─┐
│   │   ├── Task: Reward 서브에이전트     ├── 기능별 병렬

│   │   └── Task: Settlement 서브에이전트 ─┘

│   │   ├── Task: Auth 서브에이전트       ─┐
│   │   ├── Task: Profile 서브에이전트    ├── 기능별 병렬

│   │
│   └── Task: maker-agent

## 주의사항

- Phase 2 서브에이전트가 미정의된 도메인은 에이전트 본체가 전체 TC를 직접 생성
- 크로스 도메인 TC는 반드시 오케스트레이터가 생성 (도메인 에이전트에 위임하지 않음)
- 중복 제거는 보수적으로 — 의심스러우면 둘 다 유지
- xlsx 생성 전 사람에게 TC 수/커버리지 통계를 보여주고 확인 후 진행
- 중첩 깊이: 오케스트레이터(L0) → 도메인 에이전트(L1) → 기능 서브에이전트(L2) — 최대 2단계
